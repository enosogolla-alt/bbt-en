Multitier Architecture
Also known as: N-Tier Architecture  •  Most common form: Three-Tier Architecture

Multitier architecture is a software design pattern that separates a web application into distinct layers — each with a specific role. The most common form is three-tier architecture, which divides an application into the Presentation Tier, Logic Tier, and Data Tier. This separation makes applications easier to build, maintain, scale, and secure.

◆ The three-tier architecture model separating presentation, business logic, and data into independent layers
The Three Tiers Explained
TIER 1
Presentation Tier — The User Interface

This is what the user sees and interacts with directly. It includes the web browser, HTML pages, CSS styling, and JavaScript. Its only job is to display information and capture user input — it never directly touches the database.

TIER 2
Logic Tier — The Application Server

Also called the business logic layer, this tier processes user requests, applies business rules, performs calculations, and coordinates data flow between the presentation and data tiers. It runs on a web or application server.

TIER 3
Data Tier — The Database

This tier stores, retrieves, and manages all data. It consists of database systems like MySQL, PostgreSQL, or MongoDB. It only communicates with the logic tier — never directly with the user interface.

Role in Computer & Internet Technology

Multitier architecture is the backbone of virtually every modern web application — from online banking to social media to e-commerce platforms. By separating concerns into distinct layers, it allows development teams to work independently on each tier, makes applications easier to scale under heavy traffic, and improves security by ensuring the database is never directly exposed to users.

🏛
Real world example: When you log into an online store — the webpage is Tier 1, the server checking your credentials and calculating your cart total is Tier 2, and the database storing your account and order history is Tier 3.
